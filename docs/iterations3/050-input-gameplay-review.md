# 050 输入与 Gameplay 阶段性回顾

## 046–050 总览

这一组围绕同一个实际消费者推进：让现有自由相机与 demo 玩法使用手柄，同时保持项目默认、个人覆盖、
UI 编辑和运行消费的边界。没有引入新的 Manager、全局事件总线、设备专用脚本或配置历史缓存。

| 范围 | 实际职责及审查结论 |
| --- | --- |
| scene/components + camera_controller | 保存角速度并把持续轴换算为角度；鼠标仍消费位移。没有混用时间单位或增加新的相机 owner |
| demo/project.json + Lua | 输入设备差异留在项目绑定，Lua 仍使用动作名；得分停用组、调色消费和重开沿原路径 |
| ui/player_input_panel | 来源切换初始化控制及专属死区；不负责保存、运行阶段或设备采样，不缓存此前来源历史 |
| InputOverrides／PlayerInputSettings | 未改格式或合成协议；已有 UUID 未改，新增默认绑定自然继承，显式零值仍合法 |
| App／Editor | 共用相机 System 和玩家面板，没有增加两套宿主手柄逻辑；Edit 场景与历史不受运行输入影响 |
| 测试 | 单位计算、Runtime 时序、UI 草稿与真实 demo 分层；demo 两设备参数化复用已有场景装配和独立断言 |

旧个人覆盖的语义仍明确：禁用某个键盘绑定不会禁用后来新增的手柄绑定；禁用整个动作则覆盖其所有绑定。
这是既有“绑定级／动作级”区分，不为新增 demo 默认值引入迁移或清洗。
跨来源初始化与“取消草稿／恢复默认”是不同操作，没有把来源历史偷偷持久化。

## 生命周期与失败

- 持续轴只在 Runtime 普通更新中积分，暂停停止、单步使用该步时间；鼠标和手柄失去各自授权时遵守已有 Gate。
- 相机持续轴不依赖鼠标按钮，也不请求光标锁定；044–045 的捕获与 UI 解锁路径未被扩展。
- 玩家草稿校验失败仍保留旧有效数据；来源初始化不绕过保留键，文件保存和运行映射发布不在控件内执行。
- Lua 关联重载仍先整组准备，失败保留旧实例；成功后的 on_start 失败沿 Runtime 整体停止处理，不承诺回滚世界。
- 通知和输入组请求仍按各自的单一消费边界交付。只读复核未发现需要新增事件抽象或生命周期状态的缺口。
