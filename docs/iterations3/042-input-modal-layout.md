# 042 输入弹窗布局去重

## 背景与前后对比

玩家设置和玩家文件加载错误都要在小窗口中保持可达。此前两处各自包含相同的约束、居中和缩窗夹取代码，
只有初始尺寸与最小尺寸不同；修正工作区边界时容易只改其中一处。

之前，两处都自行读取 MainViewport、计算四边留白、约束尺寸和修正旧窗口位置。现在调用现有 UI 工具文件中的函数：

```cpp
// 玩家设置：保留较大的正文与固定操作区。
set_next_input_modal_bounds(title.c_str(), opening, ImVec2(800, 550), ImVec2(320, 240));

// 加载错误：opening 必须使用 OpenPopup 前记录的状态。
set_next_input_modal_bounds(title.c_str(), !already_open, ImVec2(470, 220), ImVec2(320, 160));
```

共同实现每帧计算工作区减去 16 像素后的最大尺寸，再将最小尺寸夹到最大值以内。
首次出现按可用空间限制初始尺寸并居中；已打开时保留原位置，只在工作区缩小时将窗口夹回可见范围。
所有 SetNextWindow 调用仍发生在 BeginPopupModal 之前，不改成绘制后挪动。

## 设计理由与职责

这是两个真实消费者共享的一段无状态 UI 计算，放进已有 input_widgets，不新增类、文件或布局缓存。
头文件前置声明 ImVec2；它本来就是 UI 层，不引入 Engine 反向依赖或额外数学转换。

弹窗打开／关闭、输入阻断、翻译、错误正文滚动复位、等待保存和底部操作仍由原调用方负责。
opening 不在函数内部重新推测：刚调用 OpenPopup 后 IsPopupOpen 已不能表达“原来是否打开”。
