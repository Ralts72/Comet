# 028 玩家面板的小窗口布局与覆盖状态

## 背景

026 的 App 入口和 027 的关系提示可用，但玩家面板固定为 800×550，正文多个固定高度区块会挤走底部按钮。
这在缩小 App 窗口或较小的 Play 宿主上影响取消／应用。同时，控件没有区分项目默认值与个人覆盖；
被解析器拒绝的局部补丁还可能看起来像正在生效的设置。

本项只改善已有面板的使用与状态表达，不新增输入来源、存储格式或运行时协议。

## 布局与职责

弹窗受当前 viewport 可用尺寸约束，正文滚动与根层操作栏分开。正文依然包含动作、绑定、关系和诊断；
缩小窗口不会让 Apply／Cancel／Restore All 随长正文滚到看不见的位置，较窄时按钮换行。
绑定控件根据可用宽度换行，不依靠水平溢出去访问录入按钮。

控件 ID 仍按动作／绑定 UUID 定位，只调整窗口层级；文件读取、候选请求、失败保留和输入阻断保持原协议。
不新增 Window/Layout Manager，也不把像素布局放进 Engine。

## 状态说明

每个已有绑定区分“继承项目默认”“个人覆盖”和“覆盖未生效；使用项目默认”。
失配判定来自已有合成结果的 issue 身份，不解析错误消息或重复实现 InputActions 校验。
被拒绝的覆盖继续保留供显式恢复，显示时不能把其非法值当作有效绑定。
对应绑定的输入控件禁用，Restore Binding 仍可用；类型变化仍要求 Restore Action。
不能仅换一个新键继续编辑，因为隐藏的旧无效倍率也会使新候选再次失败；这里不自动替用户删除字段。

## 验证与限制

26 项玩家面板定向 UI 全部通过，其中新增 5 项覆盖 480×320 小窗口、打开后缩小、真实鼠标录键、
继承／个人／恢复状态和被拒绝补丁的有效默认显示。正文滚动、根窗口无滚动、按钮在实际 ClipRect 中可点击均有断言。
首轮小窗测试发现根窗口额外 52 像素滚动范围：Begin 后移窗使本帧裁剪与布局坐标不一致，
改为 Begin 前 SetNextWindowPos 后消失；没有删除断言。测试未增加生产访问器。

Debug App／Editor／UI 测试构建通过，无编译警告；完整 1052 CPU、206 UI、Shader 构建契约与模块边界通过，
1 项既有原生监听用例按平台条件跳过。日志前缀 `/tmp/comet-auto3-028-`，没有 GPU 后端变化，未重复 GPU 测试。
这不是全面主题、缩放或无障碍系统，也不改变 App 当前内建英文字体和 Editor 的中英文词表来源。
