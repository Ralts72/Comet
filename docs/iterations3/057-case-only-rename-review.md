## 本机实际证据

在自动创建的临时项目中使用当前生产 `AssetSourceOperations`，先创建脚本及模块，
并确认 `actor.lua` 存在时 `Actor.lua` 也解析到它，再分别调用：

```cpp
SourceOperations::move(database, handle, "Actor.lua");
SourceOperations::move_module(database, "shared.module.lua", "Shared.module.lua");
```

希望成功的两项断言实际失败，错误分别为：

```text
asset destination already exists
Lua module paths cannot use symlink aliases
```

源码／元数据字节不变、组件原路径与身份不变、模块没有生成 `.meta` 的断言通过。
当前行为是写入前拒绝，不是丢文件。临时探针已从源码撤回，并重建测试程序；
失败用例不进入长期测试，也不把这次预期的功能缺口探针说成全套回归失败。
原始日志：`/tmp/comet-auto3-057-case-probe.log`。

## 为什么不能只放开判断

普通资产用源码／元数据两次移动；模块目前用硬链接发布目标、移除原文件，并在扫描失败后补偿。
旧模块回滚的关键逻辑是：确认原文件不存在或与目标等价后，移除目标路径。
如果把同一目录项的两个大小写拼写直接传入，移除目标也会移除原文件。
所以 `equivalent(source, destination)` 为真不能直接视为“可安全覆盖”，不同硬链接还可能拥有不同目录项。

## 下一项的最小设计

只支持同一父目录末级名称的纯大小写调整，沿既有事务执行：

```text
验证源与目标关系
  → 唯一同目录暂存名
  → 再检查目标空闲并发布目标
  → 候选扫描和身份／实际路径检查
  → 提交数据库，清理暂存
```

组件追踪源码和 `.meta` 各自所处阶段；模块保持 source-only，不引入 Handle 或元数据。
失败恢复原始拼写也要利用暂存，不直接复用大小写别名之间的旧回滚。
保留不覆盖真实目标、项目路径边界、符号链接约束及恢复失败保留可恢复文件的语义。
不创建通用 FileSystem，不修改 Scene Undo，也不自动改写 Lua `require`。

最少验收为：两类成功改名、源码打开解析新路径、扫描失败恢复原名与字节、
独立目标冲突／符号链接／不同硬链接拒绝。实际拼写必须枚举目录项检查，
因为大小写不敏感卷上旧拼写依然能够访问已改名文件。
