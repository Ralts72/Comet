## 修复：恢复默认也是一次结束录入的操作

在没有个人覆盖的绑定上，用户仍可先开始录入，再点击“恢复绑定”。原实现认为没有记录就无需操作：

```cpp
if(found == actions.end()) {
    m_error.clear();
    return;
}
// 删除覆盖并提交……
m_capture.reset();
```

因此同一操作在“已经有覆盖”时会取消录入，“还没有覆盖”时却继续等待；之后按 K 或手柄 East
又会产生新覆盖。与当前动作无关的记录不能决定恢复按钮的录入语义。

现在把取消录入移到函数入口，文件和有效绑定仍可保持无变化：

```cpp
void PlayerInputPanel::restore_binding(Uuid action, Uuid binding) {
    m_capture.reset();
    // 查找并删除对应覆盖；不存在则只清理错误，不造出默认值副本。
}
```

没有新状态、回调或失败框架；键盘／手柄共用原恢复路径。

## 036–040 架构回顾

| 范围 | 结论与处理 |
| --- | --- |
| 目录、依赖 | 共享 UI 仍只依赖输入值和 ImGui，不反向依赖 Editor；默认面板留在 ProjectSettings，个人面板由两个宿主共用 |
| 调用链 | 036 删除默认面板的 ImGui 反向键转换与无消费者继承；037 使用实际 UI 占用授权，而不是把所有修饰键禁掉 |
| 所有权 | 默认定义、个人草稿、文件基线和活动映射有不同寿命，不能为了减少成员合并成第二个输入管理器 |
| 录入寿命 | 039 的每槽连接版本只表达采样事实，不等于设备身份；040 修复无变化 Restore 漏取消，保持草稿及其他记录 |
| 渲染中的求值 | 动作区之后反馈区再次 resolve 是为了看到当帧修改；未发现瓶颈，不新增跨帧缓存或脏标记体系 |
| 可读性与冗余 | README、架构和路线图曾重复逐项补丁细节；本项按用法／协议／剩余验收分工，保留原链接锚点 |
| 测试 | 通过公开面板行为证明缺陷，覆盖空草稿、无关覆盖及两种设备；不引入生产测试访问器或私有状态接口 |

App 的 Gate 备份用于 ready 帧重算尚未消费的授权；关闭帧阻断和请求完成状态也有实际消费者。
这批状态没有因数量增多就被包装到新类中。弹窗边界计算存在小段重复，暂不为了本次回顾扩大 UI 公共接口。
