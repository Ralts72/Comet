# 038 禁用绑定仍可辨识

## 背景

032 使禁用保留个人按键和参数，但面板为避免误改而隐藏了整组控件。
一个动作同时禁用键盘和手柄后，每行只剩相同的“禁用绑定／恢复绑定”以及状态文字，
用户无法知道该启用或恢复哪一条；通过 UUID 定位控件的自动测试没有覆盖这层可见性。

## 前后变化

原先：

```text
[已禁用] [恢复绑定]
已禁用；保留个人覆盖。
```

现在仍不开放编辑，但显示该条记录保存的选择；没有个人字段时显示继承的项目默认字段。
文字明确它是禁用记录，不是当前正在生效的映射。来源／按键名称沿用 InputActions 的格式化规则，
不展示 UUID，也不创造另一套名称表。

```cpp
control = patch.control.value_or(binding.control);
scale = patch.scale.value_or(binding.scale);
deadzone = patch.deadzone.value_or(binding.deadzone);
```

有效合成结果已经删除禁用绑定，不能拿它反推保留的玩家意图。
摘要直接读取原默认 Binding 与原稀疏 patch，仅绘制文字，不改草稿或保存数据。
轴／位移及显式保留的倍率会显示数值；手柄轴或显式保留的死区同理，避免相同按键的不同绑定再次无法辨认。

## 边界与架构价值

禁用仍只切换标记，恢复默认仍删除该覆盖；Engine、JSON 格式、Runtime 重绑定均不变化。
不通过重建一份“显示用有效配置”伪装禁用状态，也不添加 UI 备份或新的展示类。
整个动作禁用时的折叠行为保持，本项只解决多条禁用绑定的辨识问题。

- 同时禁用 K 与 South 时两条翻译后的摘要均可辨认，恢复 South 保留 K；随后重新启用 K，原覆盖仍生效。
- 保留 RightX、倍率 1.500、死区 0.350 可见但没有对应输入控件；默认来源改变后的失配保留值同样只读，
  重新启用仍报告原不兼容问题，不因显示摘要而静默修正记录。
