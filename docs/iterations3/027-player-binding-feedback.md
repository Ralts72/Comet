# 027 玩家有效绑定的共享与消费提示

## 背景与前后对比

项目默认输入面板已经能解释同一个控制在不同动作组之间的关系；玩家改键面板只有控件和不兼容记录诊断。
例如把跳跃改到 K 后，用户看不到 K 也用于调色组，更无法分辨这是合法共享还是被高优先级动作组消费。

本项将关系正文提取成 `comet_ui` 的小型自由函数，两面板共用同一展示，不新增路由或回调框架。
项目面板传完整合法草稿；玩家面板传“默认值＋个人草稿”的有效合成结果，而不是原项目或未校验的局部控件值。

```cpp
const auto resolved = m_draft.resolve(m_defaults);
if(resolved) {
    render_binding_relationships(resolved.value().actions, m_selected_action, translations);
    render_diagnostics(resolved.value(), translations);
}
```

同一份合成结果同时用于关系和兼容性诊断。禁用会从有效绑定中移除对应项，恢复默认重新参与关系；
未知身份／类型漂移的补丁继续保存并报告，不能让已被拒绝的值出现在“有效关系”中。

## 设计理由与职责

`ui/src/input_widgets.*` 只读取 InputActions、选择索引与当帧借用的翻译表，并绘制正文。
遍历与文本从已有项目面板迁出；实际规则仍调用 `InputActions::compare_bindings`，不在 UI 重新实现优先级或消费规则。
折叠状态、滚动范围、草稿校验与保存流程留在各自面板。

关系是“两边动作组都启用时”的条件说明，不代表当前局的活动路由，也不保证第三个组不会继续消费输入：

- Common 动作不参与消费；同优先级或不消费的重叠合法共享。
- 高优先级 consuming 组解释消费方向，不把所有重叠统一写成冲突。
- 默认关闭的组仍展示条件关系，并标明初始关闭。
- 倍率／死区不改变控制身份；同一控制重复绑定不会重复刷同一对动作关系。

翻译通过只读词表传递，不引入 `std::function`。Editor 语言模块提供当前语言的有效词表，英文返回空表；
共享 UI 不知道 Editor 的语言枚举或 YAML 路径。玩家、项目默认值仍有不同编辑语义，不合并为一份草稿。

## 测试与限制

35 项定向 UI 通过，其中玩家面板 21 项；新增四个边界用例覆盖录键当帧的双向消费、禁用及三种恢复、
同优先级／Common／默认关闭组与借用翻译，以及失配补丁回退默认但保留原记录。
完整 1052 CPU、201 UI 与 Shader 构建契约、模块边界通过，1 项既有 CPU 原生监听用例条件跳过；
Debug App／Editor／UI 测试构建通过，无编译警告，日志前缀 `/tmp/comet-auto3-027-`。
本项未改变 GPU 后端或 Runtime 输入协议，沿用 026 的完整 GPU 回归，不重复运行。
不为查看关系产生候选或磁盘写入，合法一键多用仍允许 Apply；文件保存与运行时更新边界沿用 024／025。

本项没有设备录制、组合键、多人或运行时输入监视器，不把配置提示当成实时调试器。
后续先处理玩家面板在小窗口下的可用布局和继承／覆盖状态说明，再由真实项目决定更复杂的交互语义。
