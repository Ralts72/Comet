# 055 重命名退出时清理当前错误

## 背景与前后变化

Project 的普通资产重命名和 Lua 模块重命名共用弹窗，但普通资产的“名字没变”分支漏了一次清理。
例如把 `actor.lua` 改成非法名称 `../escape`，看到错误后改回 `actor` 并确认：
文件没有移动，弹窗也关闭了，旧错误却继续出现在 Project 面板正文。

之前同名确认只结束目标与弹窗：

```cpp
if(source == destination) {
    ImGui::CloseCurrentPopup();
    m_rename_target = std::monostate{};
}
```

现在同一分支补上：

```cpp
m_operation_error.clear();
```

## 设计理由与架构价值

错误属于当前操作；用户以原名确认结束操作后，它不应继续挂在面板上。
这一行为与已有的模块同名确认、取消操作一致。不发起无意义的移动请求，
也不为一行状态修复建立新的对话框控制器、事件或错误管理器。
资产身份、文件及 `.meta`、选中项、Undo 历史均保持不变。
