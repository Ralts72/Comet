# 030 玩家设置失败反馈与阶段性架构回顾

## 背景

026–029 打通 App 的玩家输入面板、有效绑定关系、小窗口布局和手柄按钮录入。
本次专项回顾发现两个用户可见问题：Editor 加载坏配置只写日志，点击入口像没有响应；
保存错误则位于正文最后，在小窗口中可能看不到原因，而 Apply 仍固定可见。

本项修复失败表达，不改文件格式、Runtime 重绑定协议或坏文件保留策略。

## 加载失败：共用绘制，不共用宿主生命周期

之前 App 有私有 `render_input_error()`，Editor 的 `open_player_input()` 直接返回失败，
上游 Play 请求只记录 `LOG_WARN`。现在两个宿主调用已有共享 UI 模块中的无状态绘制函数：

```cpp
bool render_player_input_error(std::string& error, bool close_requested,
    const Translations& translations = {});
```

宿主继续持有错误、决定是否加载、何时清理及是否用物理 Esc 请求关闭。
绘制函数不读取文件、不依赖 Input::Frame 或 Engine，只更新错误显示状态并返回输入阻断。
错误关闭当帧仍返回 true，防止同一个 Esc 或点击进入游戏；下一帧恢复原 Gate 流程。

Editor 的失败路径变为：

```cpp
auto settings = Comet::PlayerInputSettings::load(m_project.id());
if(!settings) {
    m_player_input_error = settings.error();
    return Comet::Result<void>::failure(settings.error());
}
```

原日志仍保留，面板不会拿一份空配置覆盖坏文件。换场景、Stop 和退出清除该宿主的临时错误；
App 的重开也沿用原清理边界。弹窗使用稳定 ID，因此切换语言不改变窗口身份；
长诊断在有限高度正文内滚动，Close 留在根窗口，小窗口约束与关闭帧阻断由共享实现保证。

## 保存失败：操作错误与草稿正文分开布局

原先 `m_error` 跟在绑定关系和诊断之后，用户必须滚到 Content 底部才能看到。
现在根窗口先绘制有限高度的 Error 区域，再绘制可滚动草稿正文，最后是固定按钮。
Error 区域自身可以滚动，既不会被正文滚走，也不会因长路径挤掉 Apply／Cancel。

只调整已有错误状态的呈现；`complete(failure)` 仍保留草稿和原运行配置，重试仍走原保存基线检查。
没有增加一套失败事件、重试队列或弹窗管理器。

## 026–030 架构回顾

| 边界 | 结论 |
| --- | --- |
| Engine 输入 | 物理帧、动作规则、稀疏覆盖和 Runtime 历史独立于 UI；共用首个手柄查询，不复制设备选择策略 |
| 共享 UI | ImGui 后端、玩家草稿、关系正文与错误绘制服务 App／Editor；不访问 Project、文件或编辑器状态 |
| 宿主 | 仍编排加载→合成→保存→重绑定；App 与 Editor 的启动／Play／错误退出不同，不为少几个成员合成一个 Manager |
| 状态 | 草稿、文件原文基线、待应用候选、有效映射分别有实际生命周期，不能简单去重 |
| Gate | App 的未消费快照用于延期帧与 ready 帧二选一，缓存阻断保障无 UI 回调帧；删除会改变输入时序 |
| 依赖 | 边界检查补入 `input_widgets.h`，防止 Engine 包含共享 UI；没有增加 Editor→平台或 Engine→ImGui 依赖 |
| 后续整理 | 项目与玩家的无状态来源／控制选择还有重复，可在后续验收项收敛；两种录入状态机使用不同输入边界，不强行合并 |

测试只补失败与生命周期的实际边界，不增加生产测试访问器。已有 UI、存储和 Runtime 测试各自负责本层；
真实宿主 Apply—生效—重开仍需单独验证，不用“单测均绿”冒充完整交互。

## 验证结果

34 项玩家面板／错误弹窗 UI 通过；完整 1053 CPU、214 UI、Shader 构建契约与模块边界通过，
1 项既有平台条件跳过。Debug 全目标与 Release App 构建通过，无新增编译警告。
测试覆盖 480×320 长错误可见、正文与错误独立滚动、实际鼠标重试／关闭、翻译切换保持 ID、
外部生命周期清错、关闭帧阻断、真实坏文件原文及修改时间不变。日志前缀 `/tmp/comet-auto3-030-`。

首轮 4 项 UI 断言失败源于测试观测字段：ImGui 的 End／PopClipRect 已把 `window->ClipRect`
恢复成父区，不代表子正文。按第三方实现核对后改用 `InnerClipRect` 和子窗口 Pos／Size，
仍检查真实绘制顶点裁剪及鼠标命中，没有放宽可见性要求或修改生产来迁就测试。

本项桌面验证只启动隔离项目并确认运行画面；原生自动点击尚未稳定触发入口，未声称保存闭环完成。
临时诊断脚本误用未开放的 print 造成一次预期外退出，改为已有 comet.log；未为验收开放新 API。
后续继续定位自动输入与真实宿主的差异，不以此次窗口启动代替 Apply—运行生效验收。

## 限制

原始解析／文件错误正文保持诊断原文，标题与按钮沿宿主词表翻译；不是通用错误本地化系统。
加载失败时没有自动重置或修复个人文件，避免用户一次误点击清掉已有配置。
