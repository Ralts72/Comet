## 停止与恢复

正常情况下至少持续 5 小时，之后可在独立验收项与收尾完成的节点结束。
8 小时截止、主额度剩余低于 5%、额度真实重置／到达初始窗口截止时间或用户要求停止，任一成立即停止开发。
每步开始、验证后、提交前和长任务间隙检查额度；持续查询失败则停止，不盲跑。
不把初始满额或重置时间秒级抖动当作重置；不购买额度、不用重置券、不切换额度池绕过限制。
权限或范围阻塞先做安全的在范围内排查，确需用户决定时报告。

触发停止后只做必要进程清理和最小记录，未验收内容保留工作区，不补做功能凑提交。
已授权在上述条件满足时暂停目标；未完成业务目标不标为完成，恢复需明确授权。
不通过等待、重复测试或无消费者 API 凑时长；范围内有效工作提前全部完成则如实报告。

## 实施、验证与记录

- 每步对应独立能力／修复：核对缺口 → 明确职责与生命周期 → 实现真实消费者 → 验证／审查 → 文档 → 本地提交。
- 最多两个辅助代理；不并发修改同一文件，主代理统一构建、测试和提交。
- 每步相关增量构建、CPU／无窗口 UI 与模块边界检查；跨模块或本轮收尾时完整相关回归及 Release 构建。
- 允许短时、串行、有超时的 app／Editor 和必要 GPU 冒烟，不操作无关进程。
  自动证据不冒充画面、真实发声或完整交互的人工验收；不因单项人工验收未做阻塞独立开发。
- 性能测量仅用于热路径修改、明确瓶颈或实际退化，不反复进行无收益全量测量。
- 每 5 项、重要跨模块能力完成或本轮结束时检查目录、职责、依赖、冗余、命名和生命周期。
  不为减少文件／成员数量创建包装层，不为减少回调机械引入事件总线，不为测试增加生产访问入口。
- `NNN-topic.md` 与代码同提交，包含代码块前后对比、原因、调用链、验证证据和限制。
  根 README 只同步真实用法；路线图不通过降低标准或删除待办宣布完成。
