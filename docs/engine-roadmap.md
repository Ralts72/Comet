# Comet 引擎路线图

更新：2026-10-16。Comet 与编辑器供作者个人学习使用，目标是职责清晰、代码易读、性能可测量的 3D 游戏引擎，保留完整的编辑、运行与内容发布闭环。
骨骼动画基础已接通；高级动画／粒子、GI 和路径追踪继续按路线图推进，独立渲染线程与更新／绘制重叠已接通，后续继续测量与优化；个人使用决定工程实现的规模，不缩小功能与算法学习目标。
当前实现与所有权见[架构文档](architecture/overview.md)，构建与操作见 [README](../README.md)。本文维护计划、取舍与验收，不累计逐文件完成日志。

## 功能定位与推进顺序

目标是能独立制作、运行和导出小型 3D 游戏，并通过实际场景学习引擎算法。现有角色 demo 是验证载体，不能成为所有能力的唯一使用方式。
下文“阶段 3～7”保留为领域索引，不代表必须逐章完成的时间顺序；实际推进以下面的功能里程碑为准。
“已有基础”表示链路可用，不等于同类商业引擎的全部功能已完成。优先级是面向本项目的判断，不是照抄其他引擎的实现顺序。

### 与主流引擎对照

对照依据为 [Godot 的稳定版功能清单](https://docs.godotengine.org/en/stable/about/list_of_features.html)、
[3D 场景导入](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/advanced_import_settings.html)、
[Unity Prefab](https://docs.unity3d.com/6000.0/Documentation/Manual/Prefabs.html) 与
[动画状态机](https://docs.unity3d.com/6000.0/Documentation/Manual/AnimationStateMachines.html)。
高阶表现参考 Unreal 的 [Niagara](https://dev.epicgames.com/documentation/unreal-engine/creating-visual-effects-in-niagara-for-unreal-engine)、
[GI](https://dev.epicgames.com/documentation/unreal-engine/global-illumination-in-unreal-engine) 和
[Path Tracer](https://dev.epicgames.com/documentation/unreal-engine/path-tracer-in-unreal-engine)。
这些系统的规模、后端和支持范围各不相同；Comet 学习对应能力，不承诺复制完整编辑器或达到同等覆盖率。

### 优先级与独立交付

P1 是近期功能主线，P2 是下一组可玩性与表现能力，G 是可穿插的算法学习专题，P3 由明确样例触发。
真实崩溃、数据损坏、CI 失败和同步错误随发现修复，不再设一个没有结束条件的“全局优化阶段”。

| P1.2 模型与复用 | glTF 节点、多 mesh／材质槽及关联纹理；Prefab 子树资产、实例化和基础覆盖；常用多选／批量放置 | 下载或从 Blender 导出一个多材质场景，在两个关卡复用；修改源内容仍保持实例身份和合法覆盖 |

### 规模与停止条件

- 以一个小型第三人称双关卡样例验证功能，另用独立参考场景验证渲染算法；不把关卡规则、胜负、装备或 AI 决策硬编码进 Engine。
- 功能完成须能创建／编辑、保存重开、App／Play 使用，并满足它实际涉及的暂停、撤销、重载与清理；不要求每个功能穷举全部组合。
- 优化由可复现瓶颈或明确算法学习题驱动。已有渲染线程、实例化、增量缓存和同步回归继续保留；没有新证据时结束局部调优，回到功能交付。
- 架构审查随新功能检查职责与复用，不作为不断新增 Manager、协议、模块和测试矩阵的独立主线。
- 保留现有三个构建入口、单 Editor 视口、中文界面、Lua 与 RmlUi；不安排商店、稳定插件 ABI、团队协作、云构建和多后端产品化。
- 真实 App／Play、高 DPI、手柄、窗口／HDR 等手工验收交给使用者；自动测试负责可复现的内容、运行逻辑与 GPU 正确性。

### 工程简化原则

- 功能目标、算法深度与工程机制分别评估。某种架构实现可以延后或改用更直接的方案，不能据此删除对应能力。
- 头文件按领域接口组织，简单枚举与结构优先复用已有的相关数据头；拆文件须有明确的职责或依赖边界收益，避免按单个类型不断细分。
- Editor 是项目描述、场景和编辑器生成配置的写入者；运行期间不支持外部工具同时改写这些文件，也不建立自动合并／修复协议。关闭 Editor 后可修改，重新打开时仍正常解析与校验。
- Lua、GLSL、RML／RCSS 等源码支持在 VS Code 中编辑。其文件监听、候选失败保留、请求 revision 与输入指纹校验属于实际开发工作流，继续保留。
- 同一人也会产生在途任务、连续保存和 GPU 异步使用；进程内版本检查、资源保活、局部失败清理不能按“单人使用”删除。
- 没有实际消费者的构建变体、可替换所有后端的框架、稳定插件 ABI、通用配置合并、长期多版本兼容、自动恢复所有罕见故障不作为前置工程。
- 模块依赖、唯一所有权与低成本检查继续保留。新抽象应减少真实重复、隔离第三方实现或明确寿命，不以类数、target 数或设计图完整度为目标。
- 性能方案用同设备、优化构建和代表场景测量；可先串行／单队列实现，后续并行或高级图规划仍保留学习与优化计划。
- 编辑器固定中文，不扩展模板市场、插件体系和通用偏好框架；窗口尺寸、面板布局等常用本地状态继续保留。
  项目模板／切换、UI 制作与导出继续服务实际内容制作，不因取消产品化框架而删除。

### 世界、会话与执行契约

当前 SceneRuntime 可独立测试固定步、暂停和单步；生产 Engine 仍拥有窗口与 Renderer，一个活动 Runtime 可供多个 View 呈现。
RuntimeSession 已保存会话值、输入组请求和重开意图；音频与物理后端已由服务拥有，System 负责场景同步。
后台任务与帧系统执行分开；App／Editor 最小化暂停模拟与绘制，仍有界接纳后台结果，恢复不追赶。当前时序见[一帧经过哪里](architecture/overview.md#一帧经过哪里)。

1. **数据与执行**：Scene 保存内容、稳定身份和结构变更；RuntimeSession 保存本局状态，服务拥有设备与执行对象。
   后续明确接触／Gameplay 通知和材质运行覆盖归属，通用结构命令按阶段末提交；不为每个 System 扩充 Scene。
2. **呈现与宿主策略**：GPU acquire／交换链重建不应隐式定义模拟行为；前后台、最小化和失焦是否暂停由宿主明确选择。
   无窗口推进复用 Runtime 时间／输入接口；不同世界加载后实体、会话和服务不串用，不以新增构建 Profile 验证此能力。
3. **阶段与并行**：固定更新、后置固定更新与普通更新已显式串行；接触逐固定步交付，结构请求在各阶段末提交。
   渲染插值已沿固定／后置阶段记录姿态；根运动已在物理求解前消费，固定步骨骼姿态也已沿同一边界插值，主绘制、阴影和挂点共用结果。
   保留系统依赖／并行演进目标，但只在接入并行消费者时建设可检查的 DAG；避免注册顺序与声明并存成为两份真值。
4. **变换与物理**：结构与配置按脏变化同步；活动／休眠回写、传送和唤醒保持正确。
   临时内存复用、Jolt 并行按规模测量；动画／root motion／脚本／动态刚体分别规定 Transform 写入权。
   渲染插值已消费前后固定步姿态与系数；动画姿态插值与根运动扩展继续验收暂停／单步、传送与实体重建，避免错误路径。

验收固定步、暂停／单步、重开、启动失败及停止清理；测量同步／模拟／回写和临时内存，不以 FPS 单项证明收益。
多世界／并行各有独立样例与资源隔离验收，不增加所有可能模式的笛卡尔测试矩阵。

### 内容类型与复制

ComponentDescriptor／PropertyDescriptor 已共享编辑、序列化与恢复；Scene clone 使用直接内容快照，保留 UUID、层级与引用，排除运行态。

- **类型扩展**：整数、嵌套结构、容器和可选字段随真实组件推进；Inspector、序列化、脚本字段和 Prefab 使用同一字段描述，热路径仍操作具体组件。
  稳定 Type／Field ID、默认值和校验保留；针对自己保存的旧内容做必要迁移，不维护未知扩展类型与长期任意版本兼容。
- **Prefab**：子树、内部引用重映射、字段覆盖与嵌套来源更新已接通，操作见[实体、资产与材质](usage.md#实体资产与材质)。后续按实际制作需求补根变体和更直观的覆盖比较，不再另建一套内容格式。
  这是实际内容功能；字段删除／类型改变诊断属于编辑结果一致性，不等同于支持运行时外部改写项目文件。
  P1 首版用门、可拾取物和角色三个实例验证：项目资产保存子树，编辑器拖放与 Lua 生成共用实例化，内部引用重映射，外部资产引用保留。
  覆盖只先支持已有字段描述能表达的值；Apply／Revert 和源更新明确哪些实例会变化，不先做任意继承层级、变体市场或可视化逻辑图。
- **协议区分**：内容 clone、实例化与存档／完整运行态快照各有含义，不能以 memcpy 或场景文件往返替代全部协议。

验收嵌套／数组组件的编辑、撤销、保存与复制一致；Prefab 新身份与内部引用正确，更新不破坏合法覆盖。

### 性能观测与规模验收

使用同设备、优化构建、场景、分辨率、种子和采样区间比较；validation／同步正确性单独跑。

- render_benchmark 已覆盖高对象／多材质、持续变换、脚本、骨骼动画、项目 Shader 及活动／休眠刚体，输出 P50/P95/P99、独立 Runtime 更新时间和实际负载计数；同一入口、构建与固定布局供后续优化比较。
  继续扩展动画混合／粒子、深层级与资源加载样例；多 View 实现后补其基线。
- CPU 分段记录更新、物理、提取、裁剪、解析／排序、录制和呈现等待；GPU 按 pass 计时，另记录 draw／实例数、分配／上传量与内存峰值。
  队列提交与呈现调用已独立采样；较长基准随采样帧数增加预热，macOS 基准明确请求主线程 QoS。
  macOS 报告更新回调中的 CPU 采样分布；交替复测先核对同一版本波动与核心调度差异，再判断缓存／并行的整帧收益。
- 物理容量分别测量刚体、接触对和接触约束，按实际场景调整缓存与内存预算，不能用刚体上限代替接触负载上限。
- 持久代理、并行、缓存和驻留预算由明确瓶颈推进；保留 p50／p95／p99 与热路径复用，不先建设跨设备认证和统一自动降级平台。
- Play／Stop、热重载、resize、加载／卸载后资源回到稳定值；等实际 GPU 完成再核对，不能用全局等待隐藏所有权问题。

## 基本边界

- Scene 的持久化数据保存组件配置、Entity UUID 和 AssetHandle，不保存 GPU 对象或运行时所有权。
  Scene 实例可持有非持久的请求及不可变 CPU 参数快照，会话值归 RuntimeSession；启停清理和在途快照寿命见架构文档。
- AssetHandle 是非零 64 位持久资产身份；EntityId 是进程内实体标识，EntityUuid 用于持久定位，二者不混用。
- AssetRegistry 是唯一 Handle → Runtime Asset 缓存。RenderResources 不建立第二份资产缓存。
  CPU MeshData／TextureData／MaterialData 位于 asset/data；材质运行时定义／准备／绘制聚合到 render/material，辅助线聚合到 render/debug。
  SceneRenderer::RenderState 保存完整兼容资源，render 执行多 pass；不为目录整理增加抽象基类。
- Engine 组合通用能力，app/editor 组合项目工作流；不把 demo bootstrap 或 ImGui 专用类放入 engine。
- 以实际职责、可测试契约和生命周期拆分，不为减少成员数量套结构体，不为对齐设计图增加转发 façade。
- 保持 C++20；通用纯逻辑先有测试，Vulkan 行为通过集成测试和 validation 检查。
- Shader 只保留实际使用的生产实现与有明确覆盖目标的测试资源；不为学习用途长期维护已被替代的模板。
- 所有格式规则以根目录 .clang-format 为准，不在路线图或 AGENTS 重复一套排版细则。

当前实现以代码和[架构与所有权](architecture/overview.md)为准；
下文的新类型名是目标职责，不意味着立即新增同名文件或类。

当前项目 `.shader` 同时保存程序组合与材质编辑 metadata，这是已接通动态 Inspector 的阶段性格式；**尚未决定迁移目标格式**。
已用一个 Program 服务两个材质实例验证独立参数值：Inspector 切换编辑保持各自数据，GPU 画面使用各自参数；
不兼容的 Shader 候选被拒绝后，两者显示洋红色错误材质，修正后恢复各自参数；已提交帧保留原画面。这证明当前实例复用路径可用，
**尚不证明**两种不同默认值或公开属性集合能共用一个 Program；出现该需求时再验证格式是否真的受限。
若需拆分，先定义旧资产的迁移、缺省规则、反射校验和 Inspector／GPU 版本一致性，再修改文件格式；不能先删 metadata 再让编辑器失去属性定义。
物理类型、binding、offset 以反射为准，编辑语义以内容声明为准，实例值以 `.mat` 为准；重复字段必须声明生成或校验关系。

开发期继续使用逐文件 `.meta` 保持稳定 Handle；项目 `.comet/cache` 只放可删除重建的产物，阶段 7 的 Shipping Manifest 从已验证资产图生成，不把开发期 sidecar 原样搬入发布包。是否改用开发期中央清单，以真实的移动、复制、合并和多人协作需求另行评估，不因参考包没有 `.meta` 就立即更换。

核心 3D 主线先验收 Program／材质／发布包；可复用效果与 Sprite／序列帧是内容需求驱动的扩展，不作为项目 Shader 或 Shipping 的前置。若接入效果，先用 BlurX → BlurY → LUT 一类可保存的顺序链验证输入输出、参数映射、失败与目标重建；若接入 Sprite，先用两个序列帧层验证帧序、播放状态和比例变体。二者都不复用 ShaderProgram 字段承载组合或时间状态。

## 阶段 3：补全资产工作流

P1 先解决常见素材能否使用：二维纹理产品／mipmap、常用材质贴图，以及 glTF 的完整模型组织。
模型导入分步保留节点层级、局部变换、多个 mesh、primitive 材质槽及纹理引用；生成的子资产具有稳定身份，重导入不静默丢失材质覆盖。
首版继续选 glTF／GLB，可由 Blender 等外部工具转换；不为覆盖文件后缀而先接多套导入库。
纹理压缩属于后续体积／带宽优化：按实际设备选择格式，验收色彩／法线质量与产品缓存，不能将压缩等同于 mipmap。

当前基线：资产身份、扫描、导入／加载、后台发布及场景引用恢复已接通；
实际行为与失败边界以 AssetManager、ImportService 及对应测试为准。

后续工作与约束：

- AssetTaskQueue 保持 AssetManager 私有；revision 复核、Force 合并与发布预算属于资产语义，
  不预建通用任务框架。出现第二个独立消费者时再评估拆分；回归继续覆盖过期结果、队列占槽和失败回收。

- Runtime 资产加载／重载共用带错误类别的 Result；失败保留旧资源，DeviceLost 不安装候选场景。
  仍需真实桌面交互验收；材质文件写入与 Runtime 发布不是全局事务，不能用统一接口掩盖各自的失败点。

- 沿[编辑器资产边界](architecture/overview.md#owner-结构)收窄源编辑与运行时加载入口。
  纹理设置／材质编辑的准备、写入、revision 和发布需有一致性协议，不能只搬文件写入造成两个提交点；
  迁移真实消费者并验收失败保留旧资源，保持唯一 AssetRegistry，不添加纯转发接口。
- SceneAssetReferences 的细粒度组件变更通知按规模完善；运行时代码新写入 Handle 的加载需求按阶段 6 补齐。
- 队列和预估工作集额度不等于进程内存或整帧保证。补进度、取消与索引发布预算，
  用真实大项目验证主线程峰值；暂时队列满与内容错误分别恢复，保留候选的 revision／输入复核。
- TextureArtifact 已随二维 mip 链接通完整像素产物、源指纹／导入设置复核和原子缓存发布；项目预准备复用相同入口。
  开发加载仍复核源文件；运行时 Artifact-only 加载随只读产品索引接入，不先复制 Mesh 的所有中间层。
- Texture 的 wrap/filter、mipmap、压缩必须接通 Sampler、Image 与上传消费者，不能只增加不生效的配置字段。
  环境立方体、IBL 预滤波与普通二维材质纹理均已接通 mip 链、上传、ImageView 与 Sampler LOD 范围；
  二维纹理默认生成完整链，颜色在线性空间过滤，Inspector 可关闭。非二次幂、1 像素尺寸与 GPU 缩小采样有自动回归。
  法线贴图已按用途线性过滤并归一化；导出模式已保留只读纹理产品及 wrap/filter 采样设置，后续按素材需求补充编辑能力。
  验收远处／斜视表面的闪烁、非二次幂与 1 像素尺寸、热重载及显存／上传开销，不把各向异性过滤当成 mipmap。
- glTF 多 mesh 子资产、node transform、material、animation、skin、morph target 需明确导入契约后逐项扩展；
  动画与骨骼的消费、版本和失败边界见阶段 6，不把导入字段支持误认为播放和蒙皮已完成。
- 补全递归依赖失效、更多资产类型；资产与 Shader 的原生文件监听按下节统一接入，
  不把手工编辑 .meta 的失败保留作为当前产品路径。
- 给 Device 提供反映实际启用 features/extensions/queues/limits/formats 的不可变能力集合，不再让使用方拼接来源。
- streaming 保留后续能力目标；先以明确需求完成资源加载／卸载，再按规模扩展占位与淘汰。内容错误等待修正或显式重试，不为所有资源建立自动重试框架；关键 RenderTarget 保持明确失败。
- Shader 编译产物、缓存键与发布 Manifest 在 metadata/导入协议稳定后设计，Shipping 不带源编译器。

验收：移动不破坏引用；失败不发布半初始化对象；旧任务不能覆盖新结果；大批量操作不长期卡主线程。
Mesh 缓存可删除重建但不替代源资产；Runtime 加载不能隐式回退 glTF 解析。

### 统一文件监听与防抖

FSEvents、后台复核及候选发布现状见[Owner 结构](architecture/overview.md#owner-结构)；
现有 Shader 防抖为 200 ms 编辑器内部默认值，扫描与 revision 更新不等待防抖。

未完成：Windows 原生后端、通知溢出／根目录恢复的完整协议、数据库结构增量索引与代表性项目帧时间验收。
发布前复核和源签名计算仍可能占用主线程；下一轮用真实项目的峰值及帧时间决定是否继续优化，
不凭合成样本或平均耗时跳过过期校验。操作和 Profiler 入口见[使用手册](usage.md#诊断与性能测量)。

- **职责与所有权**：平台层只报告文件／目录可能变化，不直接导入、编译或操作 Scene／GPU。
  资产和 Shader 共用底层监听及变更合并能力，各自按依赖关系决定重建范围；不创建全局 EventBus。
  监听注册、解除由所属项目／编辑器服务管理，连接可自动释放；切换项目、销毁服务后排队事件按 generation 丢弃。
- **原生通知优先**：macOS、Windows 分别接入平台后端并验收，平台细节留在私有实现；其他平台暂用显式兜底。
  现有后台轮询保留给不支持原生通知的平台；注册／通知失败明确报告，可通过 Refresh 或重新打开恢复。暂不扩展自动切换后端、所有文件系统异常和重连的完整状态机。
  正常空闲路径不周期读取源码、不扫描目录；主线程只消费有界事件／完成队列，目录查询与内容复核在后台。
- **按目录监听**：覆盖源码父目录、递归目录变化和缺失 include 的搜索候选，避免仅绑定旧文件对象，
  漏掉编辑器“临时文件写完后 rename 替换”的保存方式。新增目录及时注册，目录级通知转换为局部重查。
  事件可能重复、合并、乱序，不能把一次 Remove 立即视为资产永久删除；按合并后的磁盘状态与现有身份规则决策。
  排除 .comet/cache、构建目录等自产物；编辑器自身写入通过已确认内容去重，不用全局忽略时窗吞掉外部修改。
- **尾沿防抖**：以受影响资产／Shader 程序批次为合并键，而不是全局定时器；共享 include 可使多个程序分别变脏。
  使用单调时钟记录最后一次相关事件，`due = last_event + quiet_period`；新事件到来就延后该键的截止时间。
  当前 quiet_period 为 200 ms，按真实输入和编译耗时测量后调整；不把它作为项目或用户设置，
  也不将此值视为行业标准。
  例如事件发生于 0、80、150 ms，截止时间依次变为 200、280、350 ms；无后续事件才在 350 ms 后排队。
  不 sleep 主线程；持续写入只保留一个 dirty 项，不强制在仍不稳定时编译，也不拖延其他资产的更新。
- **通知只是线索**：静默时长不证明文件写完。到期后复核内容、依赖与路径解析结果；内容未变不推进实际编译／导入。
  外部编辑器保存期间的短暂缺失、占用与分段写入可做小范围有界复核；坏内容保留旧有效版本并等待新保存或显式 Refresh，不将所有读取错误都加入自动重试。
  新事件立即使相关在途候选过期；实际重建请求在防抖后合并提交，仍最多一个在途任务和一个最新后继。
  队列满保留 dirty 状态并稍后重试；发布前继续复核 revision／输入快照，不能用文件事件代替一致性检查。
- **漏事件处理**：保留启动校准、手动 Refresh 和必要的溢出诊断。完整的根目录搬走／重建、后端自动重连和休眠恢复矩阵延后；作者可重新打开项目。
  正常运行不常态双重全量扫描；需要局部重查时按 root 合并并放到后台。

验收采用可控时钟和事件注入，并增加当前使用平台的真实文件操作冒烟；Windows 原生后端接入时补对应验证：

- 空闲时无源码读取／目录扫描／重复编译；单次保存、重复事件、连续保存仅重建最终稳定内容。
- 两个无关资产独立防抖；共享 include 只更新依赖者，缺失 include 创建后自动恢复。
- 原地写、原子替换、重命名、删除后重建、目录搬移、分段写入均最终收敛，不丢资产身份或发布半批结果。
- 在途修改丢弃旧结果；队列满保留最新需求，事件溢出有诊断且可通过 Refresh 重扫恢复；项目切换后无失效回调、跨项目事件或重复发布。
- 统计原生事件数、合并批次数、重扫次数和实际编译／导入次数，确认改进的是空闲 I/O 与重复工作，而非只换调用方式。

参考依据与边界：Unreal 的自动重导入提供监视目录、过滤条件及 Import Threshold Time，支持“检测后延迟处理”，
但文档没有规定所有引擎必须采用同一种尾沿算法。见 [Unreal 自动重导入](https://dev.epicgames.com/documentation/en-us/unreal-engine/reimporting-assets-automatically-in-unreal-engine)。
Unity 6 文档列有 Windows 的 Directory Monitoring，并在导入期间输入变化时重新刷新；不能概括成所有平台都不扫描。
见 [Unity 偏好设置](https://docs.unity3d.com/cn/6000.0/Manual/Preferences.html)和
[资源数据库刷新](https://docs.unity3d.com/6000.0/Documentation/Manual/AssetDatabaseRefreshing.html)。
以上共用监听、按依赖批次尾沿防抖与 200 ms 初值是 Comet 的设计选择，不是照搬这些引擎的实现或默认值。

- 三角形级精度按需求评估；GPU ID/readback 和多 pass outline 留到阶段 5。
  真正引入 readback 时需在对应 fence/timeline 完成后 invalidate/read，不预建无人使用的系统。

验收：坐标、拾取、Gizmo 和高亮在 DPI/resize/裁切后保持一致；一次编辑手势对应一次撤销，保存后可恢复场景。

### 命令与通知编排

- 继续以 Command History 承接新的编辑入口。现有菜单／结构／资产／模式请求统一结束活动编辑；离散属性赋值复用事务 apply。
  场景环境／背景色与后处理已共用类型化 SceneTarget 的预览、提交、取消；新增同类设置不再扩充事务的类型分支。
  历史只记录内容目标及修改前后值，不记录 GPU 对象、Pass 生命周期或整个引擎快照；普通编辑与 Undo/Redo 走同一场景提取链路。
  一次手势只记录一次，提交捕获校验／归一化后的实际值，不重复恢复再重放；结构编辑仍使用有明确逆操作的命令。
  新命令沿用唯一执行者、显式结果和事务边界，不另建平行的修改路径。
  可撤销的场景修改进入历史；保存、刷新、重导入等服务操作不因入口统一就强行加入 Undo/Redo。
  持久化的 Bloom 等内容开关同样可撤销；面板可见性、相机导航及未来仅影响编辑器的临时效果预览不进入场景历史。
- 命令入口稳定后，仅对资产发布、选中对象变化、活动场景切换等真实一对多通知引入类型化事件。
  事件表达已提交的事实，不代替有返回值的命令或查询；不把整个编辑事务改成订阅者之间的隐式调用链。
- 首个试点先核对选中变化是否确有两个以上需要主动通知的消费者；若有，由 SelectionService 在状态实际改变且提交后发布带稳定身份的类型化通知，让消费者仅更新各自派生状态。若查询已足够，不为减少回调数量强行引入事件。验收切换场景、重复选择、面板销毁和 Play／Edit 往返均无旧通知或重复副作用。
- 通知通道由所属 Editor/服务持有，不预建全局 EventBus。明确派发阶段、订阅连接的 RAII 解除和重入规则；
  跨线程结果回到 owner 线程处理，载荷使用稳定 ID/revision 或自有数据，不保存组件裸指针。
- Overlay prepare/render、交换链 release/rebuild 保留有序生命周期钩子，不混入业务事件。
  场景 getter/replacer 属于访问与所有权协议，属性编辑函数属于策略回调，不能为减少回调数量硬改成事件。
- 与场景快照时点一起验证：修改在预定阶段提交，Transform 更新后再提取；失败不广播成功通知，
  面板销毁或 Scene 更换后无失效订阅，同一次提交不重复执行或重复记录历史。

### 材质与 Shader

#### 常用材质表面（P1，基础链路已接通，素材验收待补齐）

- **贴图语义**：基础色、法线、金属粗糙度、AO 与自发光已被 Shader 消费，纹理导入区分 sRGB 和线性数据，法线 mip 重新归一化。
  glTF 源切线已沿导入、缓存、普通／实例化绘制与 GPU 蒙皮保留，镜像和非均匀缩放通过像素回归；无源切线的 glTF 已接 MikkTSpace 生成，硬边／镜像 UV 接缝拆点及蒙皮权重保持有回归；复杂烘焙素材的实际观感仍待验收。
- **表面模式**：不透明、Alpha Mask、Alpha Blend 与双面已接通；材质排序、深度读写、实例化兼容性和阴影裁切共同生效，混合材质不投射实心阴影。
  首版使用常规透明排序并说明交叠限制；OIT、复杂折射和多层材质独立扩展，不作为树叶／玻璃／基础粒子的前置。
- **验收**：使用普通下载素材验证纹理方向、色彩空间、法线凹凸、粗糙度响应、自发光与 Bloom、树叶阴影和透明遮挡；
  修改、保存重开、热发布及 App／Play 使用同一材质定义。不先做 Shader Graph 或材质节点编辑器。

#### 光照与画面效果扩展（P2／G）

方向光四级阴影已接通：每个 View 独立投影与图集，纹素对齐、级联混合、距离淡出和各级 LOD／剔除共用现有链路。`shadow_cascades.scene` 用于近远覆盖、相机移动稳定性与阴影距离验收；自动回归覆盖投影、级联边界像素、帧槽复用和多 View，实际观感与关卡耗时仍需验收。
聚光灯阴影已复用深度绘制、裁切材质、LOD 与图集采样；每 View 固定四盏、每盏 512×512，候选按保守视锥筛选和实体 ID 分配，超预算数量进入渲染统计。`spot_shadows.scene` 用于四灯、光锥调整和预算验收；实际观感仍需验收。
点光源六面阴影已接入共用链路：每 View 两盏、每面 512×512，保护纹素覆盖交界处 PCF；三类灯合计最多 20 个阴影视图，每帧槽固定 32 MiB。`point_shadows.scene` 用于多面覆盖、移动与超预算验收；实际观感和多灯开销仍需验收。动态阴影分辨率、跨帧缓存和优先级调度按实测需求扩展。
基础 AO 已接入：共用 DepthPass 生成相机深度，固定 16 次采样仅衰减 PBR 环境光；开关／半径／强度沿场景保存与撤销。`ambient_occlusion.scene` 用于接触面和相机移动验收；屏幕边缘、薄物体与实际开销待验收，时域降噪和半分辨率优化按实测需要推进。
基础距离雾已接入 SceneEnvironment：雾色与起止距离沿场景保存／撤销，内置 PBR／Unlit 在透明混合前计算，无额外 pass。`distance_fog.scene` 用于近远过渡与相机移动验收；天空背景、粒子雾化和高度雾待扩展。
局部反射与静态探针 GI 首版已接通；体积雾、贴花、SSR、色调调整、景深和运动模糊分别作为画面专题，不能把后处理清单视为全部必做的前置。
局部反射探针的环境资产引用、空间范围、边缘混合和盒投影已接入，设置沿组件保存／撤销，快照固定资源版本；每 View 最多四个可见探针。Editor 已接入显式静态六面 HDR 捕获、环境源发布与现有预过滤，内容指纹提示输入过期，引用替换支持撤销；捕获不包含动画角色、非静态刚体、粒子和其他局部探针。`reflection_probes.scene` 使用自带小 HDR，可通过“烘焙反射”替换为场景捕获；场景实际观感与编辑操作待用户验收。动态反射、自动更新和更复杂探针选择按内容需要扩展，不把镜面捕获当作 GI。
保留 MSAA；TAA／时域升采样需要运动矢量、历史失效和拖影验证，待静态、角色和透明表面基本正确后再做。
GI 与路径追踪保持下方独立目标，不以加入 Deferred、SSAO 或更多后处理作为完成它们的替代。

#### 材质编辑与资产撤销

当前 `.mat` 保存模板引用、参数与纹理 Handle；Project 创建、Inspector 模板切换及动态属性已接通。
模板切换仅保留兼容参数，失败不替换已发布材质；创建和编辑的事务、回滚及在途帧行为见
[材质准备与寿命](architecture/overview.md#材质准备与寿命)。默认材质不得依赖 demo，资产 Undo/Redo 不混入场景历史。

- **材质手势与独立撤销已接通**：拖动只发布运行时预览，结束后原子保存一次；取消恢复保留的原材质及 GPU 版本。
  MaterialEditSession 拥有手势，活动期间推迟 Shader／资产后台发布；切换资产、隐藏面板和进入 Play 前结束编辑。

#### 默认资源与程序资产

- 接通引擎内置基础材质，供新模型未指定材质时自动使用；项目描述不配置 default_material。
  基础材质不依赖 demo 的纹理或材质文件，内置资源有稳定身份／解析入口和明确生命周期，不在编辑器内写死临时 Handle。
  自动默认只针对未指定材质；显式引用丢失仍保留身份并报告错误，不用默认材质掩盖坏引用。
- Shader 源分为引擎内置（engine/shaders）与项目自定义（项目 assets/shaders）；前者由引擎维护，后者随项目版本控制。
  两者最终复用程序描述、编译／反射接口和渲染消费者；区分来源与身份，不各造一套 Shader/Pipeline 系统。
  项目 Shader 的产物写入项目 .comet/cache，内置 Shader 使用引擎构建／安装产物；项目不得通过同名文件隐式覆盖内置资源。
  项目只引用内置公开契约，不包含引擎源码绝对路径；私有渲染 pass 的 Shader 不必作为用户可选材质资产暴露。
  提供可导出到项目的公共 GLSL 接口（Frame、Object、Lighting），纳入项目依赖快照；
  接口版本与 CPU／GLSL 布局一起校验，避免示例 Shader 手动复制偏移和结构声明。

Shader 基础能力与后续独立验收项：

1. 可失败创建与消费者迁移：反射／布局／Pipeline 校验、GPU 候选创建、结果处理与失败回滚完整接通，见下节。
2. 内置材质 Shader 的后台编译、失败显示错误材质、整批 GPU 发布及在途帧保活已完成；
   当前只覆盖已登记的内置材质程序和有限的布局重绑定，不等于项目 Shader 资产。
   现行调用链、重试与失败边界见[架构文档](architecture/overview.md#材质-shader-热发布)；
   原生文件监听仍按阶段 3 的共用专项推进。
3. 项目 Shader／程序资产与布局生成：补复杂参数、顶点输入／stage 间接口、外部字节码校验。
   同步完成下节“资源服务与程序版本所有权”的迁移，不把程序状态继续叠加到 SceneRenderer。
   复用上面的模板选择控件，将候选扩展为内置公开程序与项目程序，支持新增 metadata 属性驱动面板；
   当前字符串 template 引用届时定义版本迁移，转为明确来源与稳定程序身份，不按文件路径或显示名定位。
   资产撤销与文件事务一起完善；不把已有模板选择推迟到本项，也不先引入 bindless。
   基础接口校验已落地：按入口反射 user I/O、忽略 built-in，检查顶点 attribute／binding 和片元输入的来源。
   当前采用精确 32 位标量／向量格式契约，不支持的数组、矩阵、结构体、64 位与 component 打包 I/O 明确拒绝。
   后续按消费者扩展 normalized／packed 顶点格式转换、复杂 I/O、插值／附件输出及设备能力校验；
   不把这一步的保守限制说成 Vulkan 完整兼容规则，也不把反射视为完整 SPIR-V validator。

现行契约与覆盖边界见[架构与所有权](architecture/overview.md)；不迁回旧 ShaderManager、异常协议和固定间隔无限重试。

specialization 已贯通类型化值、默认值规范化、反射校验、PipelineKey 和 GPU 创建。
当前仅支持 bool/int32/uint32/float32 的固定接口变体；所有依赖 specialization 的数组长度暂不接受，
包含局部数组及派生表达式。改变数组形状需经编译期 defines 生成新字节码再反射；不把每帧材质参数变成 Pipeline 变体。

目标编辑流程：项目 Shader 源码及程序描述进入资产管线，描述组合 vertex/fragment 等阶段与入口；
编译与反射产出可用程序和参数布局，材质按稳定资产引用选择程序／模板，Inspector 按布局显示纹理槽及其他参数。
基础 float、vec4 和 sampler2D 材质属性已接通：反射核对类型、binding 与偏移，`.shader` metadata 提供名称、默认值、用途与编辑范围；不把任意单个 GLSL 文件当完整渲染方案。
切换程序时保留兼容参数，对缺失或类型变化给出默认值／诊断；编译失败显示洋红色错误材质，修正后恢复。

Shader 源码、CPU 结果与 Vulkan 对象分层；后续编辑器复用现有编译库，不另起编译实现，也不让 Shipping 链接 glslang。
后台发布同时复核请求 revision 与输入快照；监听需包含缺失的 include 候选，不能只观察成功包含的文件。
持久编译缓存、优化器、HLSL、超时／沙箱和交叉编译 host tools 按实际需求安排，不把当前编译器视为不可信源码安全边界。
Editor-only 热加载已按 debounce → Worker 编译 → revision／输入验票 → owner 反射校验／创建／绘制前切换接通。
已登记材质属性的 Layout 与参数映射随 Pipeline 一起更新。失败显示错误材质并输出诊断；
成功也不能提前释放在途帧引用的 Pipeline/Layout/材质绑定。ShaderModule 只需活到 Pipeline 创建结束。
Shipping 只消费预编译打包数据，不要求松散 .spv。

### 资源服务与程序版本所有权

当前 AssetDatabase／Registry／Manager、RenderResources、MaterialPrograms、MaterialRenderer 和 FrameSlot 的分工见
[材质、Shader 与 Pipeline](architecture/overview.md#材质shader-与-pipeline)；目标重建与程序发布已经分开。
保持稳定资产身份、不可变 CPU 版本及每个渲染域的 GPU 发布状态，编译成功或 Artifact 落盘不代表画面已经切换。

后续验收：

1. **统一程序输入**：内置公开程序与项目程序复用描述、反射及消费契约，保留来源／身份；
   扩展复杂接口和设备能力校验，不另建仅按名字缓存 ShaderModule 的管理器。
2. **更多绘制消费者**：新增 pass／渲染域时明确事务范围，全部受影响消费者准备成功才共同发布；
   目标 generation 变化使旧候选失效，不把旧 RenderPass 的 Pipeline 安装到新目标。
3. **版本与寿命**：同内容发布幂等，目标重建使用已发布快照；坏 Shader 让后续帧显示错误材质，已提交帧保持原版本。
   FrameSlot 只保活实际所用 Pipeline／Layout／绑定，ShaderModule 只活到 Pipeline 创建完成，不用全局 GPU 等待发布。
4. **关闭与切换**：旧项目 generation 的任务不得发布；先停止交付并回收消费者，Device 最后释放。

覆盖任一消费者准备失败、目标重建交错、重复发布、旧帧回收以及项目关闭／切换。
后续多设备分别确认成功，不把一个全局 active 指针当成所有渲染域已就绪。

### 可失败创建 API 与消费者迁移

公共 Result、GraphicsError、候选所有权和应用退出协议已接通；现行契约统一见
[创建与错误边界](architecture/overview.md#gpu-创建与错误)。后续验收项：

1. **命令录制／同步对象创建／运行期等待**：按实际消费者继续检查异常边界；每步同时迁移接口、生产调用方及测试，
   不保留可被业务绕回使用的旧入口，也不承诺所有函数 noexcept。
2. **ImGui 第三方后端失败（暂缓）**：先明确局部资源接管／释放和中断策略，再接错误回调；

3. **WSI 故障验收**：无呈现退避、暂态 dependent 重试和 SurfaceLost 重建已接通；

4. **原生数据边界**：PipelineConfig、viewport/scissor 按真实消费者整理；不复制全部 Vulkan 类型或预建多后端框架。
   ImGui Vulkan 适配仍允许在私有实现中使用原生接口。

每个子项同时迁移接口、生产消费者与测试；覆盖坏输入、局部创建失败、旧版本保留和关闭清理，
不以全局禁用异常或新增传播宏代替错误边界设计。

  项目 Shader 不生成 C++ 头或链接进引擎；入口、编译选项及版本等 metadata 随实际发布需求加入。
- `comet_prepare_project` 默认准备启动场景；`--export-assets` 构建多场景依赖闭包和只读产品索引，App 打包复用此入口。
- 内置嵌入模式无需附带 GLSL／生成头／中间 `.spv`。若提供源码查看或重编功能，再随功能交付源码及编译依赖。
  发布裁剪不删除开发源码，头文件嵌入也不保证保密；SPIR-V 可被提取或分析，剥离调试信息仅减少名称暴露。

验收：内置模式脱离源码／中间文件正常启动，项目产物脱离开发缓存可加载；修改项目 Shader 不重编引擎 C++；
缺失产物有诊断，发布运行不回退源码编译。

### Pipeline 两级缓存

当前对象缓存已按完整内容／状态判等，弱引用不延长 GPU 对象寿命；驱动缓存已接恢复与关闭原子保存。当前边界及后续重点：

- 驱动 PipelineCache blob 用于跨进程加速，不代替对象 key。放在 .comet/cache/vulkan 或平台缓存，
  校验 header size/version、vendorID、deviceID、pipelineCacheUUID，以及 envelope 长度/校验和。
  损坏或不兼容回退空 cache，不影响启动。
- 当前在关闭进程时自动保存，也可由 owner 显式保存；编译批次后节流按实际需要接入，不每帧写磁盘。
  Pipeline 创建/合并/保存由同一 owner 串行访问；后台 ShaderCompiler 不直接操作 Vulkan cache。
- 场景加载已显式预热实际材质／镜像组合，并先应用待生效画质；时序与所有权见[材质与管线](architecture/overview.md#材质shader-与-pipeline)。
  后续测启动、首次可见与稳定帧的创建数和耗时，按真实内容补遗漏的深度／阴影等组合；不穷举所有状态，也不在 App 引入 GLSL 编译器。
- 测试 key 等价性、兼容性和损坏输入；cold/warm 性能只做测量，不要求固定加速比例。
- 接入 Shader 发布时，MaterialRenderer 的 GPU 材质缓存必须同时跟踪 PipelineState 版本，不能只比较 PreparedMaterial。
  当前 key 复制字节码保证完整判等；若实际测量出现开销，再共享不可变代码，不能退化为 hash-only。

### GPU 资源、同步与 WSI

现有 Device、FrameScheduler、UploadManager 继续演进，不为目标名称再包一层。

- Device 管 logical device、queues、allocator、能力和设备缓存，不拥有所有资产、FrameSlot 或业务 target。
  设备候选按实际 RGBA16F 场景格式检查混合、采样与 MSAA；与目标创建复用 graphics 层校验，最终输出另查单采样能力。
- FrameSlot 管复用时点：等待 completion → 释放 retained owners → reset command/descriptor/transient arenas。
  CommandPool 按 slot + recording thread + queue family 隔离；长期材质和 swapchain image 状态不放入 slot。
- Descriptor 分 frame arena、persistent arena 和 editor-owned ImGui pool；分页 pool、object ring/dynamic UBO/SSBO
  以真实规模与测量为依据，offset 遵守设备 alignment，不能覆盖 in-flight storage。
- UploadManager 显式 batch、staging 子分配、timeline completion、ready wait 的边界保留。
  后续合并跨资产批量、细化 ring 回收；独立 transfer queue 必须补齐 ownership release/acquire 与 semaphore。
- 单帧资源用 fence + RetainedResources；Buffer／Image／ImageView／Sampler 的跨线程最后引用释放交回当前回收线程，运行期间由 RenderThread 回收，启动与退出阶段由 Main 接管。
  该销毁交接不代替完成判断；只有跨 submission/queue 的真实需求才扩展通用退休机制。
  依据实际 last-use completion，不使用“延迟 N 帧”或循环 slot index 猜完成；不允许混入任意业务 callback。
- waitIdle 可用于 shutdown、设备恢复与平台回退，不应成为常规资产替换机制；graphics fence 不代表 present 已完成。
- 运行时 format/sample-dependent RenderPass/Pipeline 需与 target 形成兼容、可替换的 generation；
  当前不兼容格式仍明确终止，不能继续绑定旧 Pipeline。
  启动输出偏好与重建固定组合分开传递，固定组合不可用不回退为另一种编码。
- **WSI 无呈现恢复**：传入非空 oldSwapchain 调用创建后，无论成功失败，旧交换链都已退休。
  当前 Presentation 已区分 no-present／dependent／surface 恢复，暂时错误有界退避，失败不从退休对象 acquire。
  临时创建失败后的重试使用空 oldSwapchain；dependent 暂时失败复用成功新代，SurfaceLost 重建并校验新 surface。
  旧资源仍须等待 graphics/present completion，再按 framebuffer → view → swapchain 顺序释放。
  规则来源：[Khronos](https://docs.vulkan.org/refpages/latest/refpages/source/VkSwapchainCreateInfoKHR.html)。

### RenderGraph 与多 pass

- 当前有序图覆盖阴影、场景颜色、可选 Bloom 与显示输出；录制和失败契约见
  [有序 RenderGraph](architecture/overview.md#有序-rendergraph)。后续多 pass 复用现有图，
  不把按声明顺序执行的单队列实现描述成自动调度器。
- Pass 声明读写 usage/subresource；imported/exported 资源明确边界状态，tracker 编译 Barrier2。
  Image 不保存单一全局 current_layout；状态属于录制/编译上下文，持久资源在提交边界交接 handoff state。
- 处理 layout 变化、RAW/WAR/WAW 和 ownership，兼容 read-after-read 不机械加全 barrier。
  跨 queue family 要成对 release/acquire + semaphore；未知输入状态或绕过 tracker 的操作必须明确声明或拒绝。
- Synchronization 2 / Timeline 已启用；API version 为 1.3 不代表所有可选 feature 自动启用。
- Dynamic Rendering 在真实多 pass/attachment 需求下评估，不为 API 更换重写阶段 4。
  检查显式 feature、ImGui/MSAA/resize、调试工具和目标 GPU；可按 pass 保留传统 RenderPass。
- 保留现有小型 Forward 场景基线；实例化与可选延迟渲染按下节独立验收，不直接替换当前路径。
- 环境照明按下节独立验收；天空盒、IBL 和 bloom 是不同职责，不把环境贴图套到普通 Mesh 材质上，
  也不与显示器 HDR 开关混为一谈。
- 显示输出已支持 App 运行时选择 SDR / 扩展线性 HDR，默认 SDR，并保存玩家的高光范围／相对白色校准；
  场景和游戏 UI 共用相对白色，Play 保留 App 选择并固定 SDR。后续按真实需求增加 HDR10/PQ、
  跨屏及系统模式切换后的安全重建，再处理编辑器 HDR 视口与 UI 亮度合成。不是下一项光源迁移的前置条件。
  内部线性 HDR 场景目标与显示器 HDR 输出分开：当前 SDR 也使用浮点场景目标；OutputPass 是最终显示步骤，不是可选 HDR 特效。
  保持线性光照／合成、动态范围和一次正确的输出编码；曝光 1 是中性倍率，不是关闭显示映射。
  不为增加开关提前建立 LDR 双管线；独立全屏输出有成本，后续仅依据实际 GPU 测量评估融合或轻量路径，不能丢失色彩转换职责。
- 已接通低频 GPU memory budget、手动 allocation dump、CPU 循环分段和场景图 CPU/GPU 计时；范围与延迟见[渲染诊断](architecture/overview.md#渲染诊断)。独立测量入口与复现命令见[使用手册](usage.md#诊断与性能测量)，须关闭 validation，区分等待、CPU 录制和 GPU，不凭 FPS 直接决定引入 RenderThread。
  现有基线包含静态共享／多材质、物体／光源持续变换及活动／休眠刚体场景；按下方渲染线程计划拆分更新与渲染，测量用于确定移交边界和验证收益，不能以个人使用取消该目标。
  并行录制与 Dynamic Rendering 分别评估；不能把减少绑定等同于减少 draw，也不以桌面呈现等待证明线程拆分的收益。
- 后处理外观参数属于项目内容，当前按场景保存；引擎提供算法与校验，编辑器提供内容编辑。跨场景预设、相机覆盖、局部区域和画质降级按真实需求扩展，不提前引入全局配置与场景之间的多级覆盖。
  纯色背景也已归属场景环境，支持保存、预览和撤销；HDR 输出、MSAA 等属于游戏显示／画质策略，可运行时修改，不与场景外观编辑混为一谈。

<a id="延迟渲染后续可选光栅路径待实现"></a>

#### 延迟渲染（可选）

面向较多动态光源的不透明场景，先记录表面数据，再统一计算光照；不是延迟提交命令、异步渲染或后处理效果。
保留现有 Forward 路径，不假设 Deferred 对小场景、带宽受限设备或高分辨率一定更快。
作为 G 类专题独立验收，不作为动画、粒子或 GI 的统一前置，也不作为游戏运行时完成的门槛。

1. **最小不透明闭环**：通过现有 RenderGraph 增加 G-buffer 与 Lighting 阶段；按实际材质需求定义
   base color、法线、金属度／粗糙度等附件，优先由深度重建位置，明确空间、精度和格式。
   光照复用现有 PBR、Light 快照、阴影和 IBL，输出线性 HDR，再复用 Bloom、OutputPass 与 UI，不复制一套显示链路。
2. **材质与混合路径**：复用 Scene 提取、资产身份、材质参数及版本发布；材质程序显式声明支持的渲染阶段，
   不能把现有 Forward Shader 自动当成 G-buffer Shader。透明和不能由 G-buffer 表达的材质保留 Forward 阶段，
   与不透明结果共享深度、在后处理前合成；明确天空背景、辅助线、拾取和选中反馈的位置及遮挡关系。
   不给每个 MeshRenderer 添加整条渲染管线，也不为两条路径建立平行资产缓存。
3. **设备与画质边界**：先验收单采样 Deferred，检查多颜色附件数量、格式、深度采样及显存／带宽预算。
   不机械套用现有 MSAA resolve 处理 G-buffer；需要现有 MSAA 时继续使用 Forward，Deferred 的抗锯齿另行验收。
   路径选择属于项目画质默认值与运行时渲染策略，不属于场景后处理开关；先支持启动选择与明确能力回退，
   运行时切换待整组目标／Pipeline 候选重建可验收后接入，不静默降低用户选择的画质。
4. **性能与生命周期验收**：扩展 render_benchmark，对比相同光源、材质、分辨率及采样条件下的 Forward／Deferred，
   记录光源数、覆盖率、G-buffer 显存和各 pass 的 CPU/GPU 耗时，不只比较 draw 数或 FPS。
   覆盖像素／深度一致性、阴影／IBL、resize、材质热更新、创建失败保留旧状态和在途附件保活。
   光源体积裁剪、tiled／clustered 光照按实测独立扩展，也可用于 Forward，不把它们等同于 Deferred 的必然收益。

它不是 Bloom 一类后处理，也不是给每个 MeshRenderer 挂一个附加 pass；作为替代 forward 场景积分的渲染模式，

#### 对象／材质多 pass

当前同一 Mesh 已可参与阴影与主材质绘制，但阴影使用固定程序，材质主绘制还没有用户定义的 pass 列表。
Scene 保存外观数据，不持有 Pass 实例／执行序列；MeshRenderer 引用网格、材质及未来必要的效果选择数据，
渲染管线统一安排阶段。先绘制这一阶段的相关物体，再消费阶段输出，而不是每个物体独立执行完整屏幕后处理链。
材质的多次绘制不必对应多个 Vulkan RenderPass／图节点；不增加附件依赖时可留在同一节点，
需要中间纹理或跨阶段读写时再声明图节点，特殊的物体内绘制顺序由阶段契约明确。

按独立验收项推进，不作为基础编辑或 Gameplay 闭环的前置条件：

1. **材质阶段契约**：结合项目 Shader／程序资产，按实际需求增加主绘制、阴影、深度、遮罩等阶段变体。
   明确阶段输入、附件与渲染状态；顶点变形／透明裁切等在相关阶段保持一致，不直接把任意 Shader 当作通用 pass。
2. **对象限定效果**：先以一个真实的对象描边／遮罩效果验收对象选择、深度遮挡、目标尺寸与合成位置。
   物体输出颜色／遮罩，图编排模糊／合成；共享算法与资源契约，不把现有全屏 BloomPass 实例直接挂到 MeshRenderer。
3. **自定义效果链**：有实际组合需求后再扩展，明确 HDR 线性阶段还是显示映射之后执行，并声明读写资源、顺序与失败策略。
   首个纵向用例用三段顺序效果检验“效果公开参数 → 各材质／Pass 参数”的映射，只保留一处可编辑的权威定义；
   覆盖保存重开、缺失引用、resize、在途保活、关闭后无多余绘制及场景内容的撤销。不提前开放任意 Pass 拖拽列表，
   也不因为参考包使用 Prefab 就把全屏链塞入场景实体层级。

#### 场景间接光照（静态探针首版已接通）

当前 IBL 只提供全局环境入射光，不计算场景几何遮挡后的间接反弹；方向光阴影也不是 GI。
先用真实的室内／室外参考场景确定静态与动态物体比例、目标设备及画质预算，再独立选择烘焙光照贴图／探针
或实时 GI 路径，不同时承诺多套算法，也不把屏幕空间近似称为完整场景 GI。

本轮选择静态辐照度探针烘焙：复用静态几何／材质／光源输入，CPU 求交计算可见性与漫反射间接反弹，产物保存低频方向辐照度与防漏光所需的可见性数据，运行时供静态和移动表面采样。它与反射捕获复用输入快照和资产发布链路；CPU 求交与光栅六面捕获分别实现，反射产物用于镜面，GI 产物用于间接漫反射，分别计能量。完成条件是可编辑烘焙区域、显式烘焙、输入变化后的失效提示、产物保存与独立 App 消费，并用有色墙面的封闭／开口参考场景对比无 GI、仅 IBL 和多次反弹；记录烘焙时间、运行显存／GPU 开销及移动物体采样限制。

CPU 探针数据、球谐采样、方向距离矩、三角形 BVH 和离线漫反射求解已接通，数值回归覆盖封闭房间能量、遮挡与有色反弹；场景组件、GPU 采样和只读导出已接入，Editor 已接入显式后台烘焙、进度／取消、输入过期提示及撤销；`gi_closed_room.scene`／`gi_open_room.scene` 自带烘焙产物和移动采样方块，本机烘焙与 GPU 成本见[使用说明](usage.md#静态探针-gi)。每 View 首版选择一个可见区域，最多 4096 个探针；移动表面按世界位置采样，区域外或没有有效探针时回退全局 IBL。烘焙使用固定世界坐标，移动区域或修改静态内容后须重新烘焙。首版按 Lambert 漫反射近似计算静态几何，读取基础色、金属度、自发光及 Alpha Mask；混合透明体不参与，法线贴图细节和镜面反弹不计入该烘焙。

1. **静态内容扩展**：按真实关卡需要增加多区域选择／混合、探针可视化与布置工具；更高频的静态光照贴图和第二套 UV 单独评估。
   延续几何、材质、光源与环境的输入指纹和资产发布，不在普通运行帧中烘焙。
   保持直接光、间接漫反射和镜面边界，避免重复计入环境能量。
2. **动态对象与实时扩展**：为移动物体定义采样或回退策略；只有静态方案不足且目标设备满足预算时，
   再评估实时探针、屏幕空间或光追方案的更新、遮挡、时间累积和失效规则。
   路径追踪作为独立渲染模式可提供参考图，不默认成为实时光栅 GI 的依赖。
3. **验收**：对比无 GI、仅 IBL 和间接光的线性 HDR 结果；覆盖漏光、几何／灯光修改后的失效、
   缺失产物回退、场景切换、显存与 GPU 耗时。GI 不阻塞阶段 6 Gameplay 闭环。

### 渲染线程与并行准备

当前主循环、同步 GPU 操作、不可变帧包及关闭协议集中在[一帧经过哪里](architecture/overview.md#一帧经过哪里)。
Main 的 Runtime 更新已与 RenderThread 绘制重叠；CPU 交接最多一帧，GPU FrameSlot 的在途寿命独立。

| 线程 | 权威状态 |
| --- | --- |
| Main | Scene／Runtime、窗口输入、Editor command、UI 前端、资产结果接纳 |
| CPU Worker | 后台 I/O、导入、解码与编译；只交付自有数据 |
| RenderThread | GPU 创建／发布／回收、目标与交换链准备、录制、提交及呈现 |

后续按实际瓶颈推进：

- **测量重叠收益**：轻负载、脚本、活动／休眠物理分别比较墙钟、P95/P99 和输入延迟；
  Main 与 RenderThread 阶段不直接相加。基准 `timing_model=render-thread-v2` 合计实际帧准备及绘制，排除交接间空闲，不与旧口径直接比较。
  `shadow_model=atlas-v3` 标明方向光、聚光灯与点光源共用的固定图集模型；比较性能时必须保持阴影模型、实际投影灯数与画质一致，不能与旧单图、仅级联或不含点光源槽位的图集直接比较。
- **固定步插值与动画衔接**：基础变换插值已接通，运行查询保持真实姿态；根运动的 Gameplay 消费与物理回写权已明确，骨骼局部 TRS 已接入呈现插值，延续传送、暂停、单步、重开和场景替换验收。
- **异步候选反馈**：同步 GPU 创建／发布仍由 Main 等待。仅在阻塞成为瓶颈后异步化，保留请求／源版本及目标 generation 复核和保存／接纳／发布顺序。
- **并行准备／录制**：先测裁剪、排序和准备；每个录制线程使用独立 CommandPool，保留队列外部同步、完成身份与单队列回退，不先建通用任务图。
- **快照与背压**：继续复用独占快照存储，测量复制／分配成本；扩展排队必须有容量和显式等待／过期帧策略，不能排队借用 RenderSubmission。

验收没有并发访问可变 Scene、UI 前端或 GPU owner；绘制错误回传、最后一帧关闭、resize、Shader 更新及资源回收通过真实回归与 validation。
App／Editor 和性能基准使用现有 RenderThread；确定性 GPU 回归保留同步 Renderer，不增加构建组合。

#### 项目 UI 入口与控制器（部分实现）

当前项目入口、Lua 桥接、候选换代、`ui.settings` 和 App／Editor 复用路径见
[项目 UI 控制器](architecture/overview.md#项目-ui-控制器)。项目拥有页面、主题、HUD 和游戏策略，Engine 提供通用能力，App 负责装配。

剩余工作：

- **真实交互与规模**：按下方清单验收 App／Play、高 DPI、手柄／IME 和界面规模；Deferred／最小化期间的推进随世界／呈现解耦一起处理。
- **资源与发布**：把现有静态依赖清单与场景依赖复用到只读导出目录，补充代码／数据绑定产生的动态资源声明，不宣称静态扫描覆盖任意 Lua 路径。
- **项目原生代码**：实际需要时允许项目 `src` 中的 C++ 控制器链接到游戏程序，继续使用现有 UI 服务和生命周期，不扩展插件 ABI 或构建组合。
- **开发叠层**：独立的 FPS／调试叠层通过显式开关装配，发布默认关闭，不把调试控件写进项目 HUD。

验收两个项目使用不同 UI 和控制器、无 UI 入口的项目不出现 demo 菜单，切换项目无需修改 App。
暂停、加载、反复打开和项目切换不泄漏输入；候选失败保留有效会话和草稿，文档替换后旧句柄失效。
App 与 Editor Play 行为一致，发布包能独立运行，宿主及 Engine UI 不依赖 demo 控件约定。

#### 真实交互验收

自动 CPU／UI／Runtime 回归已覆盖保存、失败、输入隔离与更新边界。
隔离项目的 macOS App 桌面交互已核对改键应用、取消草稿、移动／触碰计分、场景及进程重启、恢复默认与两项目配置隔离；
Editor 预览已核对 UI 显示大小。完整 App／Play 验收仍保留下面的剩余项，自动回归不替代实际交互与硬件验证。

1. 完整走通 Editor Play 的改键、应用、暂停／单步、重开、Stop／再次 Play；核对取消／失败保留旧配置，
   录入和关闭不触发游戏动作，并确认 App／Play 的实际声音输出。
2. 用真实标准手柄确认按钮映射、录入与断连重连体验；继续验证 demo 调色与游戏组切换，

#### 按实际消费者扩展

- **设备与交互**：多人设备分配、控制方案切换、组合键、长按／双击、模拟轴阈值、二维／三维动作、
  文本／IME 按需独立验收。自由相机光标锁定已接入；常驻第一人称捕获或脚本主动捕获需要实际玩法时再扩展。
  当前首个连接槽不是持久玩家身份，未被平台采样观察到的硬件替换也无法推断。
  验收设备／玩家不抢输入，断连不残留动作、重连不重放边沿；计时遵守更新阶段与暂停规则。
  自由相机已区分手柄角速度与鼠标位移；后续消费者仍须分别换算，不能直接相加后共用时间缩放。
- **输入配置资产化**：有多套方案复用、独立编辑或共享需求时，再把内嵌 project.json 的默认方案提取为资产，
  复用既有资产身份、序列化与发布校验，不新建平行管理器。保持默认方案、活动组与玩家覆盖分层；
  验收移动／改名不破坏引用、多个场景可复用、候选失败保留有效配置、已有覆盖可定位或明确报告失配。
  资产化不等于外部文件热加载；这些扩展不改变阶段 6 物理／音频与 Gameplay 主线顺序。

## 阶段 7：项目格式与发布

新建／打开项目、最近项目、项目名／启动场景和默认输入设置见[打开项目](usage.md#打开项目)。
开发 app 仍依赖源目录与导入器；项目切换通过重启进程完成，不等于发布包或原地切换。

- **原地切换**：处理未保存场景和活动属性／Gizmo 编辑，先退出 Play；取消或候选失败保留旧项目。
  排空旧任务和在途帧后释放旧场景、选择、历史、资产缓存及监视器；禁止旧项目结果发布到新项目。
  ImGui 布局跨项目共享，app 不消费编辑器上次场景状态。
  验收无需命令行选项目、取消／失败不丢修改、同 Handle 的两个项目不串资源或缓存。
- **项目模板与 Build Settings**：完善项目模板、项目设置 UI 和发布入口。
  设置原子保存，Editor 独占写入，去掉运行期间外部改写的冲突检测／合并；Save Scene 不连带保存项目描述。
  项目缓存／场景会话在 `.comet/`，最近项目／布局在用户目录；Profile、字体和 Shader 与项目内容分离。
  默认输入与玩家覆盖的归属及验收见阶段 6，编辑器快捷键仍为独立用户偏好。
- **设置归属与渐进迁移**：背景、环境照明、Bloom／曝光等外观属于场景内容；跨场景预设／相机覆盖按实际需求增加。
  MSAA／各向异性过滤属于项目画质默认值与运行时画质策略；输出模式／VSync／窗口属于应用默认策略、用户偏好和设备协商，
  编辑器窗口与预览偏好独立。不把所有 render 配置机械搬入 `.scene`，归属由功能职责决定。
  基础默认值由所属模块的 C++ 设置结构提供；启动只加载当前开发者 Profile，不维护共享默认文件或多文件覆盖协议。
  Profile 只覆盖在途帧调度、底层格式与设备限制、诊断／验证及资源预算，拒绝游戏设置和未知字段。
  用户选项通过项目设置／游戏菜单修改，项目默认值与玩家选择分别持久化；Editor 窗口沿用独立本地状态，缺省使用内置尺寸。
  开发者 Profile 在进程启动时读取，修改覆盖项无需重新编译；运行中修改设置须调用对应模块接口，不能只改启动 Config 的副本。
- **游戏设置的运行时闭环**：当前显示、画质、音量与改键的合成／保存／应用见
  [输入主链与配置边界](architecture/overview.md#输入主链与配置边界)，菜单和用法见 README。
  项目 Lua＋RmlUi 定义界面与档位，Engine 提供具体能力，App 只装配服务；玩家选择按项目 UUID 隔离。
  后续按实际内容校准档位，补纹理／IBL 质量策略、HDR10/PQ、跨屏适配及必要的亮度校准，不建立通用偏好框架。
  窗口逻辑尺寸、framebuffer 像素和内部渲染比例分别表达；UI 保持输出尺寸，画质调整不缩小控件。
  App 的尺寸／窗口／输出模式试用保留 15 秒确认，确认才保存，取消／超时恢复；Play 只改离屏预览，不改 Editor 主窗口与节奏。
  帧率上限和物理固定步独立；后台／失焦策略沿世界与呈现解耦主线完善。
  真实验收：App 修改无需重启、重开恢复、两个项目不串设置、失败保留草稿；Play 不污染编辑器状态。
  实际呈现模式、HDR 屏幕效果和 App／Play 交互由使用者验收，CPU／离屏测试不代替硬件效果。

- 项目、场景、材质、`.meta`、开发者 Profile 和编辑器快捷键统一使用 JSON。
  当前格式版本不匹配直接报错；需要升级自己已有内容时提供对应迁移，不建设长期多版本兼容框架，不提前统一 ImGui ini 与二进制缓存。
- **游戏数值数据资产**：CSV 表格与 JSON 嵌套定义已接入，统一为 GameData CPU 资产；字段类型、范围、ID 和资产引用共用校验。
  源数据归游戏项目 `assets/`；CSV 字段说明随文件导入／移动／删除，Inspector 提供只读预览与源码打开。Lua data 属性参与场景依赖闭包，查询返回独立副本；导出统一 JSON 产品。
  Demo 双关卡收集反馈已使用数据资产；解析、脚本隔离、字段说明失效与脱离源码的导出加载有回归，表格编辑／刷新与 App／Play 实际观感待验收。
  后续按内容增加表间记录引用和编辑效率，不预建通用 Schema 平台或装备／Buff 框架。
  基础数值与角色实例的装备／Buff／当前属性分开，具体游戏规则归项目，不写入开发者 Profile。
- .comet/cache 继续存二进制派生产物与索引；Shipping Manifest 只含运行时身份、依赖和打包位置，
  不带松散 .meta、源资产与 editor importer 配置。打包前验证启动场景及所引用程序／材质／纹理等依赖闭包，
  缺失、类型不符或产物损坏明确失败；发布包脱离开发机缓存和源码目录可独立加载，重复打包的索引结果可复现。
- 开发日志写入项目 `.comet/logs/`，独立 App 日志／缓存写入用户目录；打包隔离启动已纳入测试，日志轮转、自动保存与崩溃恢复按需推进。
- 开发期 Scene Schema 不匹配直接报错；为已有场景提供必要的一次性升级，功能扩展不要求维护所有历史格式。

验收：示例可从编辑器打包成独立程序，不依赖仓库源路径；新贡献者能按 README 初始化与验证。

### 构建与运行成本验收

- 本地 Makefiles／Ninja 在可用时自动使用 ccache，保留显式 launcher。真实工具命中、冷编译／单 cpp／公共头与分支切换分别测量；配置 fixture 不等于加速证据。
- PCH 与高传播头只按实际重编／内存／磁盘收益调整；serialization 与 shader_contracts 经三轮独立编译测量后关闭各自 PCH，每个构建目录减少约 37.7 MiB；前者完整编译持平、单 cpp 增量略慢，后者完整编译更快。其余模块继续按数据决定，不为复用 PCH 拉平依赖。
- 无阴影 fallback、不变姿态蒙皮复用、阴影先裁剪后 LOD、启动管线预热已接通；按固定场景分开比较 CPU、GPU、上传量和驻留，保留同步与失败回归。
- ScriptSystem 结构／资产扫描、导航启动构建／产品加载／运行查询、动画求值／IK／插值、路径追踪构建／上传／dispatch 已有独立统计。先测代表规模，再决定脚本受控写入、共享动画库绑定与几何 refit／BLAS-TLAS。
- Runtime Loader 的产品读取／开发导入编译依赖、Scene 不同寿命字段与 Lua 领域绑定，随真实消费者继续收窄；不增加 Manager、多 DLL 或自动注册协议。算法学习目标保持原优先级。
