# 003：CI 有界构建

## 背景与验收

阶段 4 的跨平台验证需要一个可完成、可诊断的 CI 基线。001 的 Linux 运行在构建期间被取消，
没有进入测试，也没有报告 C++ 编译错误。日志显示 Make 在约一秒内启动了数十个 engine 编译任务。
取消原因尚未确定，不能把日志当作已经证明 OOM。

## 前后对比与设计

- 之前：`cmake --build --parallel` 未提供数值，Make 可以启动无界并发任务。
- 现在：CI 明确 `--parallel 2`，适配有限 CPU/内存的 runner；本地构建策略不变。
- Job 最长 30 分钟，CTest 单个测试程序最长 120 秒；失败保留 CI 日志，不无限等待。

限制调度资源是构建系统职责，不增加运行时线程类，也不调整 C++ 代码来掩盖基础设施问题。
不改变测试集合、降低测试断言或跳过 GLFW/Vulkan 测试。另修正 README 中“名称不支持撤销”的过期说明。

## 测试与限制

- `git diff --check` 通过；核对现有 ci-release build/test preset 和工作流命令。
- C++ 源码不变，沿用 002 的 Debug/Release 各 344 tests 本地通过结果。
- 远端需要推送新工作流后验证，不能在当前提交中宣称 Linux 已通过。后续迭代记录真实 CI 结果。
- 001 CI run 34047676502：failure，Build 被取消，测试 skipped；不计入跨平台成功。
