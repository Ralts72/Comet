# 011：平移 Gizmo 的本地轴与吸附

## 背景与前后对比

此前平移手柄固定沿世界 XYZ 轴连续移动，不能沿已旋转物体的本地轴拖动，也不能按固定步长移动。
本项扩展已有 TranslationGizmo，不新增一套拖动控制器或历史命令。

| 之前 | 之后 |
| --- | --- |
| 固定世界单位轴 | World／Local 设置；Context 保存实际世界方向 |
| 投影、求参数和应用位移各自取固定轴 | 三处使用同一 Context 方向，显示方向与实际移动一致 |
| 连续距离 | 可选 Snap，按 Step 量化相对于起点的世界距离 |
| 只有变换／相机／布局上下文取消条件 | 设置变化或本地轴方向变化也取消未完成拖动 |
| 无平移工具设置入口 | 现有 Viewport 工具栏的 Tool 菜单，不增加画面浮层 |

## 代码与算法

`TranslationGizmo::Settings` 是该交互的值配置：`Space`、是否 Snap、正数 Step，默认 World、关闭吸附、0.25。
`set_settings()` 拒绝非法空间值、非有限／非正步长。真正改变配置时先取消已有事务；相同配置不触发取消。

`make_context()` 为三个轴计算方向：

- World：直接采用世界单位轴。
- Local：`parent_world * local_rotation * axis`，随后归一化。
- 不使用实体自身 scale，因此自身负缩放不反转手柄，自身零缩放也不使平移手柄消失。
  父级变换仍参与方向和世界到父空间的逆变换；父级不可逆时沿用已有拒绝逻辑。

`make_handles()` 用该方向投影，`axis_parameter()` 用同一方向与鼠标射线求最近参数，
`update()` 用同一方向产生位移。没有只转动显示箭头而仍按世界轴更新组件的旁路。

拖动时先计算 `distance = current_parameter - start_parameter`，启用吸附后使用
`round(distance / step) * step`。沿归一化轴生成世界位移，再通过父级逆矩阵的方向变换（w=0）
转成组件 translation 的增量。相对起点吸附不会把一个非整格物体在开始拖动时强行跳到绝对网格点。

释放仍由 PropertyEditTransaction 比较前后值后提交；未跨过半步、最终位置未变时不新增历史。
操作过程不因自身平移改变轴，但外部旋转改变 Local 方向时会回退当前 translation 预览，保留外部旋转修改。

## UI 与架构价值

- Tool 菜单提供 Space、Snap、Step；Play 不显示编辑工具菜单，活动拖动期间工具栏仍禁用。
- 菜单只编辑交互配置，不写 Scene Camera、不创建 Scene 历史、不保存为组件字段。
- 设置类型留在 Gizmo 内部命名空间，投影与拖动数学仍不依赖 ImGui。
- 原有父级逆变换、裁剪／DPI 映射、输入互斥、UUID 与 generation 事务边界全部复用。
- 未引入每种坐标系一套类，也没有修改 engine／Shader／第三方代码。

## 测试结果

- Debug／Release 全部构建成功，各 **391 tests** 通过；变更代码 clang-format 和 diff 检查通过。
- 新增 4 个纯交互测试：旋转与自身负／零缩放、本地轴经过非均匀父级后的位移、相对正负吸附与空历史、
  非法设置及设置／轴方向变化取消。
- 新增 1 个真实 ImGui 帧测试：Tool 菜单切换 Snap、Space 不改变 Scene，也不产生历史。
- 既有透视／正交、DPI、裁切、父级不可逆、失焦、拖出图像和捕获释放回归继续通过；完整图形日志无 VUID。
- 首次编译修正了测试调用 Vec3 专用 Math::normalize 处理 Vec2 的错误，改用既有 glm Vec2 算法。
  未进行桌面人工操作或截图验收；本项 Linux CI 待推送后确认。

## 限制与后续

- 这是相对距离吸附，不是绝对世界网格、表面或顶点吸附；Step 始终是世界单位，不是缩放后的组件单位。
- 非均匀父级使 Local 仿射基可能不正交；本项保留真实变换后的轴，不用正交化偷偷改变拖动语义。
- 设置只在当前编辑器会话保存，没有增加项目／场景格式字段或新快捷键。
- 本次仍只有平移；旋转和缩放作为后续独立验收项继续推进，届时再统一 Gizmo 模式命名与配置。
